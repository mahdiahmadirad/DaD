# TASK-0000: Bootstrap the DaD repository

## Status

Complete

## Outcome

Establish the minimum durable context needed to continue developing DaD as its
own reference implementation, without implementing the framework.

## In scope

- Define the repository scope.
- Define the target audience.
- Define the core principles.
- Define the non-goals.
- Design the intended repository structure.
- Establish repository-wide working instructions.
- Record this bootstrap task.

## Out of scope

- Architecture Decision Records (ADRs)
- specifications
- framework implementation
- development or validation tools
- GitHub Actions or other CI configuration
- a command-line interface
- examples
- design or implementation of future phases

## Constraints

- DaD must remain AI-agent neutral.
- DaD must remain useful to teams that do not use AI.
- This repository must become the reference implementation of the framework.
- Documentation must be no larger than needed to guide subsequent work.
- Later phases require explicit approval and their own bounded tasks.

## Deliverables

- `README.md`
- `PROJECT-VISION.md`
- `AGENTS.md`
- `TASK-0000.md`

## Acceptance conditions

- A new contributor can identify what DaD is and its current maturity.
- The intended audience, framework scope, principles, and non-goals are
  explicit.
- The proposed repository structure distinguishes project intent, tasks,
  decisions, specifications, implementation, verification, tools, and
  examples.
- Repository-wide instructions govern both humans and AI coding agents without
  depending on a vendor.
- The four requested documents are the only Phase 1 additions.
- No future-phase artifact or implementation is present.

## Completion evidence

- `README.md` provides the entry point, current status, document map, and
  intended structure.
- `PROJECT-VISION.md` defines the durable product direction and boundaries.
- `AGENTS.md` defines repository-wide implementation and phase rules.
- This task records the scope, constraints, acceptance conditions, and
  completion outcome.
- The repository contains no ADRs, specifications, tools, automation, CLI, or
  examples.
