# TASK-0004: Publish the first DaD CLI release

## Status

Complete

## Outcome

Publish and verify the first public DaD CLI release through the approved
tag-driven pipeline, leaving complete installation, integrity, and
cross-platform evidence.

## In scope

- Confirm the release-automation task is complete and its checks are current on
  the intended release revision.
- Select the first release version according to the approved compatibility
  policy.
- Finalize the matching dated changelog section and release notes.
- Create and push the immutable release tag.
- Allow the approved workflow to validate, build, attest, and publish the
  GitHub Release.
- Verify every required release asset, checksum, attestation, version string,
  and release metadata.
- Exercise and document direct installation on Windows, Linux, and macOS.
- Update repository status and entry-point documentation made inaccurate by
  the first public release.

## Out of scope

- Changing the release architecture or distribution contract.
- Fixing release-pipeline defects without returning to a separately bounded
  implementation task.
- Replacing or moving a published tag or asset.
- Signing, notarization, installers, package managers, or automatic updates.
- Publishing targets or channels not required by the approved specification.
- Announcements outside the repository and GitHub Release.

## Constraints

- Begin only after TASK-0003 is `Complete`, ADR-0002 is `Accepted`, and
  SPEC-0003 is `Approved`.
- Treat tag creation and public release publication as externally visible,
  irreversible actions requiring explicit maintainer approval.
- Publish only from a clean, reviewed revision whose required checks pass.
- If source or artifact correction is required after tag publication, select a
  new semantic version rather than reusing the tag.
- Record limitations honestly, including unsigned artifacts and architecture
  targets that were built but not executed natively.

## Acceptance conditions

- Explicit maintainer approval identifies the exact release revision and
  semantic version before the tag is pushed.
- The dated changelog section, tag, executable version output, release title,
  and release notes identify the same version.
- All required Windows, Linux, and macOS validation gates pass for the tagged
  revision before publication.
- The GitHub Release contains exactly the required target archives and checksum
  file, with no missing or unplanned DaD assets.
- Every published checksum verifies and every required asset has provenance
  associated with the correct repository, workflow, tag, and source revision.
- Direct archive installation and `dad --version` are exercised on Windows,
  Linux, and macOS, with architecture-specific limitations recorded.
- The release and its assets are immutable and installation documentation
  points users to the verified release.
- Completion evidence records the release URL, tag, commit, checks, native
  installations, checksum verification, provenance verification, and known
  limitations.
- No out-of-scope channel, signing behavior, target, or announcement is
  introduced.

## Completion evidence

- Published
  [DaD 0.1.0-rc.1](https://github.com/mahdiahmadirad/DaD/releases/tag/v0.1.0-rc.1)
  as a GitHub prerelease from tag `v0.1.0-rc.1`, which resolves to approved
  commit `9b66ed9634be2c95d725fe9523633c0040b74ee5`.
- GitHub Actions
  [release run 30309568375](https://github.com/mahdiahmadirad/DaD/actions/runs/30309568375)
  passed tagged-source validation on Windows, Linux, and macOS before building
  the draft, verifying its artifacts, attesting the archives and checksum
  manifest, and publishing it.
- The release is titled `DaD 0.1.0-rc.1`, is marked as a prerelease, and uses
  the matching dated changelog section as its release notes. Text and JSON
  execution of the downloaded macOS arm64 binary both reported
  `0.1.0-rc.1`.
- The published DaD asset set contains exactly the five required archives and
  `dad_0.1.0-rc.1_checksums.txt`. Every downloaded archive passed its published
  SHA-256 checksum and the repository release verifier confirmed archive
  names, root contents, executable names, version behavior, checksum coverage,
  and absence of unplanned files.
- GitHub provenance verified for all six published assets against repository
  `mahdiahmadirad/DaD`, signer workflow `.github/workflows/release.yml`, source
  ref `refs/tags/v0.1.0-rc.1`, and source commit
  `9b66ed9634be2c95d725fe9523633c0040b74ee5`. Because the local network blocked
  Sigstore's TUF CDN, verification used the official Sigstore trusted root
  from pinned `sigstore/root-signing` commit
  `1a5caf04455a1e545f38bc6b1f5a6a508b0c4c3f`.
- GitHub Actions
  [installation run 30310108243](https://github.com/mahdiahmadirad/DaD/actions/runs/30310108243)
  downloaded the public archives, verified their checksums, extracted and
  placed the executable on `PATH`, and confirmed `dad --version` natively on
  current hosted Windows, Linux, and macOS runners.
- Repository-level immutable releases are enabled for future publications.
  GitHub documents that the setting is not retroactive, so this first
  prerelease is immutable by project policy rather than hosting enforcement;
  its tag and assets must not be moved, deleted, or replaced.
- The archives remain unsigned and not notarized. The native installation run
  covered each hosted runner's architecture; other required cross-compiled
  architectures were checksum and structure verified but not executed
  natively.
- No signing, notarization, installer, package-manager, automatic-update,
  nightly-build, extra-platform, or external announcement behavior was added.
