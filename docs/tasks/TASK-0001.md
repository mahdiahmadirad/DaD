# TASK-0001: Implement the DaD CLI

## Status

Complete

## Outcome

Deliver the specified DaD CLI as a tested, cross-platform Go codebase.

## In scope

- Implement every v1 command in SPEC-0002.
- Implement the platform, output, diagnostic, root-discovery, determinism, and
  filesystem-safety contracts in SPEC-0001.
- Embed canonical reusable documentation and prompt resources from their
  authoritative repository files.
- Add proportionate unit and command-level tests.
- Verify native behavior on macOS and cross-compilation for Windows and Linux.
- Reconcile repository entry points and working guidance made inaccurate by
  the implementation.

## Out of scope

- installers, release archives, signing, and package-manager publication;
- CI or GitHub Actions;
- GUI or editor integrations;
- network, hosted-repository, issue-tracker, or AI-service integrations;
- automatic semantic documentation review or reconciliation; and
- commands not defined in SPEC-0002.

## Constraints

- Use the single Go codebase accepted by ADR-0001.
- Keep runtime behavior offline and version-control independent.
- Do not give the CLI authority to approve project decisions or lifecycle
  changes.
- Preserve the canonical Markdown sources as the only maintained copies of
  embedded resources.
- Do not begin packaging, distribution, or later tooling phases.

## References

- [ADR-0001](../adr/ADR-0001.md) governs the implementation language,
  package structure, and resource-embedding approach.
- [SPEC-0001](../specs/SPEC-0001.md) governs the CLI platform and public
  interface contract.
- [SPEC-0002](../specs/SPEC-0002.md) governs command and repository behavior.

## Acceptance conditions

- `dad init`, `new`, `list`, `status`, `context`, `check`, and `prompt`
  implement the specified text and JSON behavior.
- Mutating commands support dry runs, conflict refusal, atomic document writes,
  and concurrency-safe number allocation.
- Root discovery and document operations work without Git or network access.
- Tests cover valid behavior, malformed repositories, failures, deterministic
  output, and concurrent creation.
- The full test suite, formatter, and static analysis pass on macOS.
- The CLI cross-compiles successfully for Windows and Linux in addition to the
  native macOS build.
- Repository documentation reflects the implemented state.
- No out-of-scope packaging, CI, integration, or future command is introduced.

## Completion evidence

- Implemented the v1 command surface in `cmd/dad` and the reusable CLI,
  repository, document, diagnostic, and operation packages under `internal/`.
- Embedded the canonical templates, methodology overview, and official prompts
  directly from their authoritative Markdown files; resource tests confirm the
  embedded content is exact.
- Added unit and command-level coverage for root discovery, initialization,
  document creation, listing, status, context assembly, structural checks,
  prompt access, text and JSON output, failure behavior, path safety,
  deterministic output, and concurrent number allocation.
- `gofmt -l .` produced no paths, `go vet ./...` passed, `go test ./...`
  passed, and `go test -race ./...` passed on macOS.
- `go test -cover ./...` reported 88.9% statement coverage for embedded
  resources, 67.0% for `internal/cli`, and 75.9% for `internal/dad`.
- A process-level concurrency exercise created eight tasks with unique
  sequential identifiers, left no lock artifact, and passed `dad check`.
- Native macOS amd64 and arm64 binaries, a static Linux amd64 binary, and a
  Windows amd64 binary compiled successfully. Windows and Linux test binaries
  also cross-compiled successfully, including the Windows-specific tests.
- Two clean macOS arm64 builds made with `-trimpath` were byte-identical.
- Running `dad check` against this repository completed with zero errors and
  zero warnings.
- Windows and Linux binaries were compiled but not executed in the current
  macOS environment. Runtime validation on each supported operating system is
  release validation; release automation and packaging remain outside this
  task.
