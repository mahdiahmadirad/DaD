# TASK-0001: Implement durable webhook acceptance

## Status

Ready

## Outcome

Implement the approved partner webhook acceptance contract using a durable
inbox.

## In scope

- Add the inbox persistence model and migration.
- Add authenticated `POST /partner-events` handling.
- Return stable receipts for new and duplicate events.
- Add repository, service, and contract tests for the approved behavior.

## Out of scope

- downstream event processors;
- inbox cleanup;
- partner provisioning; and
- operational user interfaces.

## Constraints

- Existing database migrations are immutable.
- Authentication must finish before payload persistence.
- Request handling must not execute downstream processing.

## References

- [ADR-0001](../adr/ADR-0001.md) governs durable receipt, identity, and the
  separation between acceptance and processing.
- [SPEC-0001](../specs/SPEC-0001.md) governs the HTTP contract and acceptance
  behavior.

## Acceptance conditions

- The migration creates a unique inbox identity for `(partner_id, event_id)`.
- The endpoint conforms to every behavior in `SPEC-0001`.
- Concurrent delivery of the same identity produces one inbox record and a
  stable receipt.
- Repository, service, contract, migration, and existing regression tests
  pass.
- No downstream processor or retention behavior is introduced.
