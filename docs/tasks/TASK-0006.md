# TASK-0006: Publish the docs/tasks CLI prerelease

## Status

In Progress

## Outcome

Publish and verify the next DaD CLI prerelease containing the canonical
`docs/tasks/` behavior from the latest reviewed `main` revision.

## In scope

- Select the release version under the approved pre-1.0 compatibility policy.
- Finalize the dated changelog entry and current-release README link.
- Verify the intended release revision and create its immutable tag.
- Allow the approved workflow to validate, build, attest, and publish the
  GitHub Release.
- Verify release metadata, required assets, checksums, provenance, version
  output, and native Windows, Linux, and macOS validation evidence.
- Record concise completion evidence after publication.

## Out of scope

- Changing CLI behavior, release architecture, or the artifact contract.
- Fixing release-pipeline defects without a separately bounded task.
- Replacing or moving a published tag or asset.
- Signing, notarization, installers, package managers, new targets, automatic
  updates, or announcements outside the repository and GitHub Release.

## Constraints

- [TASK-0005](TASK-0005.md) must remain complete on the intended revision.
- [ADR-0002](../adr/ADR-0002.md) and
  [SPEC-0003](../specs/SPEC-0003.md) govern the release.
- Treat the path change as a breaking pre-1.0 public-contract change and state
  its migration requirement explicitly.
- Publish only a clean reviewed revision whose required checks pass.
- If a source or artifact correction is required after tag publication, use a
  new semantic version rather than reusing the tag.

## Acceptance conditions

- The selected version is `0.2.0-rc.1`, a minor-line prerelease reflecting the
  breaking pre-1.0 change to generated and discovered TASK paths.
- The dated changelog, tag, executable version, release title, and release
  notes identify the same version.
- Required native validation passes on Windows, Linux, and macOS before
  publication.
- The GitHub Release contains exactly the five required archives and checksum
  manifest, and every checksum verifies.
- All six release assets have provenance for the correct repository, workflow,
  tag, and source revision.
- Completion evidence records the release URL, tag, commit, CI run, artifact
  and checksum verification, provenance, native validation, and known runtime
  limitations.
- No out-of-scope release behavior or distribution channel is introduced.

## Completion evidence

Record evidence only after the approved release is public and verified. Until
then, this task makes no claim that the release exists.
