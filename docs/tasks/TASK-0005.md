# TASK-0005: Move TASK documents under docs/tasks

## Status

Complete

## Outcome

Make `docs/tasks/TASK-NNNN.md` the canonical location for DaD task documents, migrate the framework repository and examples to that structure, and update the CLI so initialization, document discovery, numbering, creation, context resolution, checks, and tests follow the new location consistently.

## In scope

- Change the documented DaD convention for TASK files from repository root to `docs/tasks/`.
- Move existing DaD repository TASK files into `docs/tasks/` and repair relative references.
- Move TASK files in maintained examples into their local `docs/tasks/` directories and repair references.
- Update CLI document discovery and `dad new TASK` path generation.
- Ensure `dad init` creates the required task directory structure as needed through normal file creation behavior.
- Update CLI specifications, repository guidance, examples, and automated tests that encode the old path.
- Run formatting, vetting, and the full Go test suite.

## Out of scope

- Changing TASK document semantics, lifecycle states, numbering rules, or templates beyond path-related references.
- Redesigning ADR or SPEC locations.
- Adding automatic migration of third-party repositories that already use root-level TASK files.
- Publishing a new CLI release.

## Constraints

- Preserve existing TASK identifiers and Git history as far as repository moves allow.
- The final repository must have one canonical TASK location: `docs/tasks/`.
- The CLI must not silently continue treating root-level `TASK-*.md` files as canonical after this change.
- Documentation, examples, executable behavior, and tests must agree on the new path.

## References

- [SPEC-0002](../specs/SPEC-0002.md) defines CLI document locations and repository behavior.
- [docs/DOCUMENTATION.md](../DOCUMENTATION.md) defines canonical document locations and lifecycle rules.
- [AGENTS.md](../../AGENTS.md) defines repository-wide working rules.

## Acceptance conditions

- Canonical documentation states that TASK documents live at `docs/tasks/TASK-NNNN.md`.
- Existing framework TASK files live under `docs/tasks/` with valid links.
- Maintained examples use `docs/tasks/` for TASK files.
- `dad new TASK` creates `docs/tasks/TASK-NNNN.md`.
- Repository loading, `dad list`, `dad status`, `dad context`, and `dad check` discover TASKs from `docs/tasks/`.
- Automated tests cover the canonical TASK path and reject or ignore root-level TASK files according to the documented convention.
- `gofmt` leaves changed Go files formatted.
- `go vet ./...` and `go test ./...` succeed.

## Completion evidence

- Migrated the framework TASK history (`TASK-0000` through this task) from the repository root into `docs/tasks/` and repaired affected relative references.
- Migrated the maintained minimal and medium examples to their local `docs/tasks/` directories and updated their working agreements and README links.
- Updated `docs/DOCUMENTATION.md`, `AGENTS.md`, `README.md`, and `SPEC-0002` so `docs/tasks/TASK-NNNN.md` is the single canonical TASK location.
- Updated CLI repository discovery, document path validation, and `dad new task` so TASKs are discovered and created only under `docs/tasks/`. Root-level `TASK-*.md` files are no longer treated as governed TASK documents.
- Added and updated automated tests covering TASK creation, parent-directory creation, context and check behavior, concurrent numbering, canonical path validation, and the explicit exclusion of legacy root-level TASK files.

- No release tag or public CLI release was created. The path change remains in the `Unreleased` changelog until a later release task publishes it.
