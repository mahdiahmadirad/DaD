# TASK-0003: Implement CLI release automation

## Status

Complete

## Outcome

Implement and verify the approved versioning, changelog, continuous
integration, and cross-platform release-assembly pipeline without publishing a
public DaD release.

## In scope

- Replace the manually maintained CLI release version with the approved
  release and development version-resolution behavior.
- Add the authoritative changelog and initial unreleased entries.
- Add repository-owned GoReleaser configuration for the required targets,
  archives, checksums, and release notes.
- Add GitHub Actions CI and tag-triggered release workflows with the approved
  validation gates, permissions, immutable action references, and provenance.
- Add automated snapshot, archive-content, checksum, and version-consistency
  verification.
- Update contributor and installation documentation made inaccurate by the
  implementation.
- Validate the complete pipeline without creating a public Git tag or GitHub
  Release.

## Out of scope

- Creating or pushing a release tag.
- Publishing a GitHub Release or other public artifact.
- Selecting or announcing the first public release version.
- Signing, notarization, installers, package managers, or automatic updates.
- Adding targets not required by the approved specification.
- Changing CLI behavior unrelated to version resolution.

## Constraints

- Begin only after ADR-0002 is `Accepted` and SPEC-0003 is `Approved`.
- Preserve all CLI contracts in SPEC-0001 and SPEC-0002 except the explicitly
  approved version-source change.
- Use the smallest workflow permissions that satisfy publication and
  provenance.
- Keep snapshot assembly reproducible locally without publication credentials.
- Do not use a successful snapshot as evidence that public publication has
  occurred.

## Acceptance conditions

- Development, injected release, versioned module, and invalid version sources
  produce the approved deterministic version behavior.
- Text version output, JSON version output, and embedded prompt version
  metadata agree in automated tests.
- CI runs formatting verification, `go vet ./...`, and `go test ./...` and
  provides native Windows, Linux, and macOS coverage with the required shells.
- A clean non-publishing snapshot produces exactly the approved archive and
  checksum set.
- Automated checks verify archive names, contents, executable names, version
  output, checksum coverage, and absence of unplanned files.
- Release automation is tag-only, gated by native validation, uses minimal
  workflow permissions, pins third-party actions immutably, and defines
  provenance for every required asset.
- The changelog and README satisfy the approved maintenance, installation,
  verification, and unsigned-artifact disclosure requirements.
- All repository and release-configuration checks pass without publishing a
  tag or release.
- No out-of-scope distribution channel or platform integration is introduced.

## Completion evidence

- Added tag-derived and versioned-module version resolution with a `dev`
  fallback, shared Semantic Versioning validation, and agreement tests for
  text, JSON, and embedded prompt metadata.
- Added `CHANGELOG.md`, `.goreleaser.yaml`, pinned CI and release workflows,
  internal changelog extraction, and archive/checksum/version verification.
- The release workflow validates natively on Windows, Linux, and macOS, gives
  only the publishing job `contents`, identity-token, and attestation write
  permissions, creates a draft, attests both archives and the checksum
  manifest, and publishes only after verification.
- With Go 1.26.5, `gofmt -l .` returned no paths, `go vet ./...` passed,
  `go test ./...` passed, `go test -race ./...` passed, and `dad check`
  reported zero errors and zero warnings.
- GoReleaser 2.17.0 validated the configuration and twice produced the five
  required `0.0.0-snapshot` archives plus checksum file. The two clean
  snapshot sets were byte-identical, every SHA-256 checksum verified, every
  archive had exactly the approved root contents, and the native macOS arm64
  artifact passed text and JSON version execution.
- Actionlint 1.7.12 accepted both workflow files. Direct builds confirmed
  `dev`, injected `1.2.3-rc.1`, and invalid-injection fallback behavior.
- GitHub Actions run
  [30223415384](https://github.com/mahdiahmadirad/DaD/actions/runs/30223415384)
  passed against commit `43bb5f0674a7d5252fb5b15d02c6eb7ff0499b2d`:
  formatting, vet, and tests passed natively on Windows, Linux, and macOS;
  PowerShell, Command Prompt, and POSIX invocation checks passed; and the
  release snapshot was assembled and verified successfully.
- No Git tag, GitHub Release, attestation, or public artifact was created.
